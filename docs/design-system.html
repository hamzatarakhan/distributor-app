Internal reference · extracted from distributor-app

One palette, one set of components, every screen.

This is the complete token set and component vocabulary the Sales Rep app is built from. Copy the tokens verbatim into a new project's theme file, rebuild these same primitives once, then compose every screen from them — that's the whole trick to two apps looking like one family.

00Overview

The look and feel isn't a stylesheet bolted onto screens — it's an architectural rule, enforced everywhere:

Tokens live in one file. theme/tokens.ts exports colorsByScheme, spacing, radii, typography — nothing else in the app defines a color, a px value, or a font weight.
One hook reads them. useTheme() returns { colors, spacing, radii, typography, scheme }, resolved for the active light/dark/system mode. Every component and screen calls this — never scheme === 'dark' ? … : … inline.
A small component library sits between tokens and screens. ~20 primitives (this doc) compose the tokens once each. A screen imports Button, Card, ListRow — it never touches a raw View/Pressable styled by hand.
No custom typeface. The system font (San Francisco on iOS, Roboto on Android) is used everywhere, at a fixed 7-step size/weight scale. Nothing to load, nothing to license, and it always matches the OS.

01Color tokens

Every screen-facing color is semantic (colors.primary, not "#0A6EBD"). Light and dark are two complete, independently-tuned palettes — dark isn't light with a filter over it.

Light
Dark
Brand color: #0A6EBD (light) / #3B9EE5 (dark) — dark mode brightens the brand hue rather than reusing the light one, so it still reads as vivid against a near-black background.
Every semantic color that appears as a fill also has a *Tint (≈10–16% opacity wash, for backgrounds) and primary additionally has a *Border (≈22–30% opacity, for a tinted card's edge). This is how every tinted pill/card/badge in the app is built — never a flat pastel color, always the real semantic color at low opacity.

12Navigation chrome

Each tab has its own active tint instead of every tab sharing one brand color: Visits → primary, Stock → special (violet), Orders → warning (amber), Invoices → success (green), More → info (blue). Inactive tabs are always textFaint. Icons swap to a filled variant on the active tab (name vs name-outline).

Headers: card-colored background, no shadow (headerShadowVisible: false), a border instead — flat, not floating.
Pull-to-refresh tint is always colors.primary, wired once inside <Screen>.

13RTL & locale

RTL is manual, never native. Every row-laying-out spot reads isRTL from useLocale() itself and picks isRTL ? 'row-reverse' : 'row' — I18nManager.forceRTL() is never used; that flag only takes effect after an OS-level relaunch the app can't trigger on itself.
The shared Text component already defaults its own textAlign to the locale. Only override it when a value column deliberately sits opposite its label (e.g. a price aligned right even in Arabic).
Two locales shipped end-to-end: en / ar, via react-i18next with two flat JSON files kept in lockstep, key-for-key.

15Porting checklist

To make another app look and feel like this one, in order:

  • Copy theme/tokens.ts verbatim — colors, spacing, radii, typography, unchanged.
  • Rebuild ThemeProvider + useTheme() — same shape: mode (system/light/dark) persisted, resolved colors handed down.
  • Rebuild the ~20 primitives in this doc — Button, Card, ListRow, Badge, IconBadge, Money, FilterChips, SearchBar, QtyStepper, Sheet, ResultSheet, ConfirmSheet, StickyActionBar, EmptyState, ErrorBanner, Skeleton, StatCard/StatRow, CountBadge, Screen, Text, Icon. Every screen composes only these.
  • Wrap every list/detail screen in the same Screen pattern — loading/error/empty/pull-to-refresh, never hand-rolled per screen.
  • Give each tab its own accent color — don't default every active tab to one brand blue.
  • Pick the tone vocabulary once — success/warning/info/special/neutral — and never invent a sixth.
  • No custom font, no literal hex/px in a screen file — if either shows up in review, it's a sign a token or component is missing, not an exception to make.
